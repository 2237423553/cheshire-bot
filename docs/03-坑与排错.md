# 坑与排错（下篇）

> 35 个真实踩过的坑（坑 1 到 35。坑 28 是「上下文键名不匹配」大坑，机器人曾全程失忆；
> 坑 31 是「模型装看不见」——服务端拉不到视频居然不报错；
> 坑 34 是「模型谎报画好」——跳过工具 mimic 成功话术，提示词劝不住的那种）。
> 文档中的「中篇」= [docs/02-功能与机制.md](02-功能与机制.md)。

## 一、踩过的坑（重装必看）

坑 1：QQ 必须是 NTQQ（9.9.x）
经典版老 QQ（9.7.x）完全不支持。判别：安装目录有 resources\、versions\、app\ 是 NTQQ；
老 QQ 是 Resource.9.7.x.xxxxx 这种资源包命名。

坑 2：官网「往期怀旧版」= 经典版
提供的是 9.7.25 及以下。旧版 NTQQ 要去 im.qq.com/pcqq/support.html 的「全新NT架构」标签。
别用 9.9.25.42744（XSS 漏洞，看到特定代码会自动执行）。

坑 3：PowerShell 脚本编码
PS 5.1 默认按 GBK 读 .ps1，UTF-8 无 BOM 中文会乱码。
解法：脚本别出现非 ASCII，路径用 $PSScriptRoot，中文用 [char] 码拼。

坑 4：OneBot 两套令牌
HTTP / WS 各有一个 accessToken，用错报 1401 unauthorized。

坑 5：QQ 媒体 URL 没扩展名
真实格式看 file 字段。拿 URL 判格式会误判「格式不支持」。

坑 6：QQ 把媒体和 @ 拆成多条消息
解法：被 @ 时回溯自己发的最新视频（见中篇 4.4）。

坑 7：QQ 语音是 SILK v3，无解
文件名 .amr 但字节头是 SILK_V3。GLM 不认、ffmpeg 8.1 不认、pilk 没编译出模块。
已放弃，机器人如实说「听不了」。

坑 8：会话头要求（分服务商）
OpenCode Go 强制 x-opencode-session，缺了报 MissingSessionID，还要求专属 User-Agent。
CommandCode Provider 不需要这些，纯 Bearer 即可。换服务商时先探一下要不要。
⚠️ 换模型工具会带上自定义头，但**不会自动删掉** x-opencode-session；
   换到不需要它的服务商时多一个头一般无害，但要知道它在。

坑 9：思考参数（各家、各档位不一样）
MiMo 文档只写 enabled / disabled（默认 enabled）。
**{type:'auto'} 实测可用** —— 就是 MiMo Agent 里的「自动」档，模型自己决定想多深；
简单题思考 token 和默认一样，复杂题会加深。机器人现在用 auto（config.mjs）。
MiMo：reasoning_effort 会报 400；无效值可能被静默当成 enabled。
想换档位改 config.mjs 的 thinking。callLLM / selfcheck / thinkingLabel 三处用同一套判断，
改一处要三处同步。

坑 10：思考模型的回复分两个字段
message.content 是正文，message.reasoning_content 是思考过程，别发出去。
MiMo 和 GLM 都这样。思考很能吃 token，
如果设了很小的 max_tokens，会全部花在思考上导致 content 为空（见坑 19）。

坑 11：工具中途撤掉 tools 会吐工具语法
某轮不传 tools 时，模型会用文本伪造工具调用，这段会原样发到群里。
解法：每轮都带 tools（含工具回填后的续聊轮）；再用 cleanToolArtifacts 兜底清理，
提示词加「禁止用文本模拟工具调用」。

元教训：往 AI 工具调用里塞文本时，不要出现工具协议的标签字面量。
整理本文档时就踩过，内容里的结束标记会把工具调用截断。
所以视频描述的标记用〔〕而不用尖括号。

坑 12：压缩要保持消息配对
如果把 tool 角色的回填消息删了、留下孤立的 assistant(tool_calls)，接口报 400。
按完整轮次（user 到 assistant 到 tool 到 assistant）为单位删，保证首条是 user/system。

坑 13：sendReply 参数名不能叫 text
会遮蔽从 @snowluma/sdk 导入的 text() 构造函数，导致 text(chunks[i]) 变成
「把字符串当函数调用」，抛 TypeError。

坑 14：切分时短块必须合并
短段落各自成条，被条数上限硬砍就丢 80% 内容。见中篇 6.2。

坑 15：like 匹配 SnowLuma 会误杀 MCP 服务
PowerShell 的 -like 不区分大小写，写 -like "*SnowLuma*" 会连 Cherry Studio 的
snowluma-mcp 一起匹配上，于是启动脚本的「清理旧进程」会把 MCP 服务杀掉。
解法：改成匹配「跑的是 index.mjs」且「不是 mcp」：
    $_.Name -eq 'node.exe' -and $_.CommandLine -like '*index.mjs*' -and $_.CommandLine -notlike '*mcp*'

坑 16：SnowLuma 起两个实例，你看到的是空壳
手动双击「SnowLuma」时若已有一个在跑，第二个抢不到 5099，日志报
「port 5099 is in use, using 5100 instead」。5100 那个 WebUI 里没有任何消息，
而且两个实例会抢 QQ 会话和媒体 rkey。
解法：只用「一键启动」（它会先杀旧实例）；自检会报「发现 N 个实例」。

坑 17：媒体过大是静默跳过的，而且报错在 bot.err
console.warn 走 stderr，所以在 bot.err 里，不在 bot.log 里！
而且「没有 url/file 字段」「下载到 0 字节」这两条路径以前一声不吭就 return null，
日志里什么都查不到。实测 22MB 视频被 15MB 上限丢掉，模型只能瞎猜「一片黑乎乎」。
解法：上限提到 maxMediaBytes（现 100MB）；四种失败都记日志，并把原因直接发到群里。

坑 18：让模型「自己随机」不靠谱
固定提示词下它每次都往同一舒适区钻（连着推汉堡、午餐清一色盖饭）。
加「幸运数」也只改善一部分。解法：本地清单 + 脚本真随机抽签，模型只写推荐语。见中篇 8.1。

坑 19：思考模型 + 小 max_tokens = 正文为空
思考模型思考内容也计 token。
实测 max_tokens 设 16 时，全部花在 reasoning 上，content 返回空字符串、finish_reason=length。
解法：聊天请求不要设 max_tokens（现在就没设）。
排查「模型不回话」时先看 reasoning_content 是不是被截断了。

坑 20：历史在 LLM 调用之前写入，媒体会被发两遍
askLLM 会把 history 和本次 userContent 一起发给模型；
若先把这条用户消息写进 history 再调用，同一条消息出现两次，图片双倍计费。
解法：pushHistory 放到 LLM 调用之后（现在的写法）。

坑 21：图片只认 data URL，不吃 HTTP 外链（模型相关）
GLM 系传 image_url 填 http 链接会报 400「图片输入格式/解析错误」；
填 data:image/...;base64 内联就正常。
mimo 系图片 base64 正常。机器人本来就是下载 QQ 媒体再转 base64，所以无影响；
但拿外链图去测会误判成「不支持视觉」。
另外极简测试图（1x1 像素）可能报同样错误，要用真实图片测。
模型 ID 也别抄错：z-ai/glm-5.3-flashx 和 z-ai/glm-5.3-flash 是两个模型、两种价格。
（准确 ID 用模型列表核对，别凭官网页面猜。）

坑 22：Exa MCP 的响应是 SSE 格式，不是纯 JSON
mcp.exa.ai 返回 event: message 加 data: {...}，直接 JSON.parse 整个响应体会炸；
notifications/initialized 返回空体，也要容错（判空再解析）。
握手后必须补一条 initialized 通知，服务端才认；会话靠 mcp-session-id 响应头维持，
可能被服务端回收，调用报错时要重新握手再试一次。

坑 23：Exa MCP 的 web_search_exa 要求 query 和 objective 成对给
只传 query 会失败。objective 是「这次搜索想达成什么」（哪些页面该排前、要抽什么事实）。
解法：模型的工具定义里加 objective 参数让模型自己填；漏填时脚本用 query 顶上。

坑 24：用 spawn(detached, stdio:'ignore') 起 bun 会静默退出
Windows 上 bun 是 shim，detached + ignore 起的进程活不过父进程，日志里什么都没有。
解法：用 PowerShell Start-Process + -RedirectStandardOutput / -RedirectStandardError，
和「一键启动」保持一致。重定向还有个好处 —— 崩了能在 bot.log / bot.err 里查到。

坑 25：PowerShell 重定向子进程时父进程不退出
一旦 PowerShell 脚本用 -RedirectStandardOutput 起了 bun，子进程会继承 stdout 管道，
如果外面再用 execFileSync 捕获输出，PowerShell 就一直挂着（ETIMEDOUT）。
解法：执行那段用 stdio:'ignore'，进程数验证另开一条命令查。
这个坑在「一键启动」和「切换模型」里都踩过。

坑 26：官网控制台地址不是 API 地址
常有人直接粘 https://opencode.ai/console/wrk_xxx/go 这种页面地址，
它不是能 POST 的端点。切换模型工具里做了映射表：
    opencode.ai/console/*      -> https://opencode.ai/zen/go/v1/chat/completions
    commandcode.ai/console|provider -> https://api.commandcode.ai/provider/v1/chat/completions
另外 /v1 结尾会自动补 /chat/completions。
不认识的地址就按「没写版本号 -> 补 /v1/chat/completions」处理。
拉列表端点由 chat 端点反推：去掉 /chat/completions 换成 /models。

坑 27：换模型必须「先验证再写盘」
直接把新配置写进 llmstate.json 再重启，一旦 key 错 / 模型名错 / 端点错，
机器人会哑掉，而且旧配置已经丢了。
解法：切换流程是「拉列表 -> 发极小请求验证 -> 通过才写盘 -> 再重启」。
验证失败时原配置原封不动。

坑 28：★ 上下文存取键名不匹配，机器人全程失忆
pushHistory 用裸数字键 history.set(123456789, ...)，
historyForApi / buildSystem / #清空 却用字符串键 history.get('group-123456789')。
两套键永远对不上 => **模型每一条消息都是全新对话，多轮记忆从来没生效过**，
而且没有任何报错，日志看起来一切正常。

症状：上一句刚说的话下一句就忘；追问「刚才那个视频/图」说没收到；
第二条相似消息的 prompt_tokens 和第一条几乎一样（tok=606 vs 604 —— 铁证：
历史若在，第二条必然更大）。

根因：sessionId 重构成 group-<gid> 时，写入侧漏改。

教训：
1. 存取同一个 Map，键名必须走同一个构造函数/常量，别手拼两次
2. 「上下文不连贯」先查 prompt_tokens 有没有随轮次增长，一分钟定位
3. #上下文 显示的占用来自 promptTokens（真实请求数），它正常 ≠ 历史正常，别被误导

坑 29：视频 base64 有 50MB 隐性上限（MiMo）
MiMo 官方：URL 方式 ≤300MB；Base64 方式的**字符串** ≤50MB（约等于原片 37MB）。
机器人 maxMediaBytes 100MB > 37MB，大视频转 base64 必然超限。
解法：视频改走 URL 直传 —— QQ 原始链接直接给模型，
不下载不转码，300MB 上限；本地文件拿不到链接才退 base64（此时受 37MB 约束）。
另外 MiMo 视频支持 fps（0.1~10，默认 2）和 media_resolution（default/max）参数，
写在 video_url 那个 part 上，可以调精细度。

坑 30：思考模式下多轮工具调用必须回传 reasoning_content
MiMo 官方文档明确：开启深度思考时，历史中带工具调用的 assistant 消息
**必须完整回传 reasoning_content 字段，否则 API 返回 400**；
缺失还会导致指令遵循下降、幻觉增多。
解法：工具循环里 push assistant 消息时带上 reasoning_content（bot.mjs 已做）。
开思考档（如 auto）的 Agent 类产品都要注意这条。

坑 31：★ 服务端拉不到视频时不报错，模型「装看不见」（B站直链首秀踩到）
B站直链直传 MiMo 偶发翻车：API 照样 200、照样计费两万 prompt tok，
模型却回「我无法访问Bilibili的视频链接」这种拒答话术。
根因是模型服务方那一把没拉动 CDN 直链（节点是抽签的，那次抽到 upos-sz-estghw；
本机裸拉 206/200 都正常）。同一条视频立刻重喂就好 —— 纯偶发。
两个教训：
1. **「传了链接但模型说看不到」先怀疑服务端拉取失败，别信 prompt_tokens** ——
   视频请求的 tok 是粗估值（6分50秒 19468 / 5分32秒 20090，毫无线性关系），看不出拉没拉成
2. 失败的总结绝不能进缓存 —— 那次废话被 2h 缓存存了，重发同链接秒回废话
解法（bilibili.mjs 已做）：拒答检测（/无法(直接)?(访问|观看|查看|处理)|不能…(视频|链接)|无法观看/），
命中就重取直链（新签名新节点）重喂，最多 3 次；仍失败明着报错让用户稍后再发。

坑 32：启动脚本结尾的 ReadKey 在输出被管道时会挂住
_start-all.ps1 结尾 [Console]::ReadKey($true) 靠「无控制台时抛异常」进 catch 兜底，
但输出接了管道（| grep 等过滤）时它不抛异常、直接等按键，命令永远不返回。
解法：重启机器人直接跑脚本别接管道；接了就事后把残留 powershell 掐掉
（bot 本体是独立后台进程，不受影响）。

坑 33：太小的图被 highway 拒收（error_code 921）
测试发图用了张 85×85 的小图，highway 直接拒（error_code=921），报「发送失败」。
正常尺寸的真实图片（实测 320×240 起步无压力，2~3MB PNG 也通）没问题。
教训：发图失败先看图本身——过小/过假（纯色块）都会被拒，不是令牌或接口的锅。

坑 34：★ 模型谎报「画好了」——跳过工具 mimic 成功话术（提示词劝不住）
画图功能刚上线就出事故：模型不调 generate_image 工具，直接模仿上下文里
「画好啦喵～」的成功话术回一句，群里干等图片永远不来。第一反应是改提示词，
实测没用——模型会「省略步骤演结果」，同族还有坑 31（装看不见）。
对策全部上代码闸（提示词劝不住的 never 用提示词解决）：
1. **标志位**：本轮真调过 generate_image 才算画过（drewImage 标志）
2. **出口检测**：没调过工具但回复含「画好/画完/这就画/马上画」（含承诺式）→
   注入系统提示打回重画
3. **根治 = 意图强制路由**：画图/生视频句式直接脚本接管
   （翻译 → 生成 → 发群），模型全程没有装成功的机会（见中篇 12.2 / 13）
通用教训：对「模型会演」的场景，闸要立在代码出口，不能立在模型的自觉上。

坑 35：SDK 默认 30s 超时掐大媒体慢传
发 2~3MB 的图走 highway 上传偏慢，SDK 默认超时 30000ms 到点直接报「发送失败」，
图其实还没传完。视频更大更容易踩。
解法：所有发媒体的调用**显式传 timeoutMs**——发图 120s、发视频 300s。
顺手规则：凡涉及大 payload 的 OneBot 调用，超时一律显式给，不信默认值。

## 二、故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 完全没反应 | SnowLuma 或机器人没起 | 跑一键启动，看自检表哪项是叉 |
| **多轮对话失忆、接不住上文** | **上下文键名不匹配 / 历史没进请求** | **对比相邻两条消息的 tok，几乎相同=没带历史，见坑 28** |
| **B站总结回「无法访问视频」** | **服务端偶发拉不动直链，API 不报错** | **引擎自动重试（最多3次）；还失败就稍后再发，见坑 31** |
| 隔轮问视频/图片说没收到 | 媒体原片只在当轮可见 | 既定设计（描述式），见中篇 4.1/4.2 |
| WebUI 报「未检测到可加载 QQ 主进程」 | 装的是经典版 QQ | 换 NTQQ（9.9.x），见坑 1 |
| SnowLuma 里没消息 | 起了两个实例，看的是 5100 空壳 | 只留一个，跑一键启动，见坑 16 |
| 5099 打不开 | 端口被占自动退到 5100 | 启动器和自检都会扫 5099-5109 |
| 1401 unauthorized | HTTP/WS 令牌混用 | 见坑 4 |
| MissingSessionID | 缺会话头（仅 OpenCode） | 见坑 8 |
| 回复 400 | 思考参数错、消息配对错、图片是外链或缺 reasoning_content | 见坑 9、12、21、30 |
| 模型只思考不回答 | max_tokens 太小 | 见坑 19 |
| 群里出现 XML 标签 | 中途没传 tools | 见坑 11 |
| 视频发 URL 方式报错 | 链接过期/不可公网访问 | 退 base64 通道（注意 37MB），见坑 29 |
| 搜索失败、报 MCP 相关错 | 会话失效 / SSE 解析 / 缺 objective | 见坑 22、23 |
| 搜索突然开始报错或变慢 | Exa 匿名限流收紧 | exaMcpUrl 加 ?exaApiKey=key |
| 搜索结果不相关 | query 是关键词堆砌或用了中文 | 语义化英文描述（中篇 9.4） |
| 说格式不支持但明明是 mp4 | 用 URL 判格式 | 看 file 字段，见坑 5 |
| 图/视频没进来 | 被拆成第二条消息 | 回溯补媒体，见中篇 四 |
| 视频说加载失败 | 超上限或地址过期 | 看群里「[媒体]」那条的说明，见坑 17 |
| 日志里找不到媒体报错 | console.warn 走 stderr | 去看 bot.err，见坑 17 |
| MCP 服务突然没了 | 被启动脚本误杀 | 改匹配条件，见坑 15 |
| 「吃什么」老是重复 | 只靠提示词随机 | 用 foods.mjs 抽签，见坑 18 |
| token 消耗突然翻倍 | 媒体被发了两遍 | 见坑 20 |
| 图片报「输入格式/解析错误」 | 用了 HTTP 外链图 | 转 base64 data URL，见坑 21 |
| 回复被切成小碎片 | 短块没合并 | 见坑 14 |
| 回复刷屏超 3 条 | 模型没按预算写 | 调小 maxReplyChunks 或改 lengthHint |
| 加粗被抹掉 | stripMarkdown 开着 | 改成 false |
| 指令没反应、群里静悄悄 | 指令抛错没回给用户 | 看 bot.log，catch 里要 reply |
| 语音听不了 | SILK v3 编码 | 已放弃，见坑 7 |
| 切换模型后机器人哑了 | 没验证就写盘 / key 或模型名错 | 删 llmstate.json 恢复默认，见坑 27 |
| 切换模型提示「重启失败」 | PowerShell 捕获输出挂住 | 见坑 25 |
| 切换后进程数 0、bot.log 没更新 | detached spawn 起不来 | 见坑 24 |
| 拉列表报 404 或返回 HTML | URL 填成控制台页面且没被识别 | 见坑 26 |
| 自检能过、聊天报错 | 自检和 callLLM 请求头不一致 | 两处都要带 llmHeaders，见上篇 四 |
| 重启命令一直不返回 | 脚本结尾 ReadKey 被管道挂住 | 见坑 32 |
| @ 说画图没反应、回了普通聊天 | 画图句式没过三道门（超 80 字 / 无画字） | 换「画一张××」句式；bot.log 搜「画图意图」看路由日志 |
| 画画失败提示被审核拦 | 中转审核过敏，正常内容也可能拦 | 换个描述再试；机器人会如实转告拦截原因 |
| 画画报 429 / Key 无效 | 中转限流 / Key 被停用或限额打满 | 前者自动重试；后者去服务商控制台恢复 |
| 生成视频失败（429 / 502） | 中转限流或网络波动 | 下载段已自动重试 4 把；提交段稍后再试；查控制台额度 |
| 视频发群报超时 | highway 传视频慢被默认超时掐 | 已设 300s 显式超时；再失败看 bot.err |
| 生成的视频没发出来还报「超上限弃用」 | 成片超 15s 被硬闸拦下 | 正常设计（省额度）；要更长改 vidgenMaxSeconds |
| @ 点视频回「暂停营业」 | 总闸 vidgenEnabled=false | config.mjs 改回 true 重启 |
| B站总结没触发 | 链接不在文本段里（分享卡片/JSON段） | 现只认文本里的 BV/b23.tv，见中篇 十 |

## 三、常用命令

一键启动（推荐）
    一键启动.cmd

换模型（本地，不在群里）
    切换模型.cmd

重跑自检
    复检.cmd

只起机器人
    qq-group-bot\start-bot.cmd

看当前模型配置
    cd qq-group-bot
    bun run switch-model.mjs --show

B站视频总结（命令行，和机器人共用引擎）
    bun run bilibili-summarize.mjs <B站链接或BV号> [想问的问题]

看实时日志
    powershell Get-Content qq-group-bot\bot.log -Tail 50 -Wait

看报错（媒体问题看这里）
    powershell Get-Content qq-group-bot\bot.err -Tail 50

看 SnowLuma 日志
    powershell Get-Content SnowLuma\snowluma.log -Tail 50

手动杀进程（注意别匹配到 snowluma-mcp）
    powershell Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like "*bot.mjs*" } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
