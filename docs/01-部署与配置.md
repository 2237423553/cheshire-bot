## 二、一键启动（推荐，双击即可）

双击 `一键启动.cmd`（或桌面快捷方式）。

`_start-all.ps1` 一次干完 5 件事：
1. 杀掉已有实例（SnowLuma + 机器人，幂等，双击多次不会起两个）
2. 启动 SnowLuma（隐藏后台，日志 `SnowLuma\snowluma.log`），扫 5099-5109 等就绪
3. 启动机器人（隐藏后台，日志 `qq-group-bot\bot.log`）
4. 自动弹出管理后台（用探测到的真实端口）
5. 打印打勾自检表

要点：机器人会自动等注入，启动顺序随意，SnowLuma 就绪后自己连上，不用重启。
启动器本身不存模型/搜索配置，配置是机器人启动时现读 config.mjs（+ llmstate.json）的。

其他入口：
- 只起机器人：`qq-group-bot\start-bot.cmd`（此时 SnowLuma 须已跑着）
- 单独起 SnowLuma：别和一键启动同时用，会造出第二个实例（见下篇坑 16）
- 重建桌面图标：`_mkshortcut.ps1`

## 三、换模型（本地工具，不在群里）

双击 `切换模型.cmd`。

流程：输 URL + API Key → 拉模型列表 → 选序号或输名字 → 验证能跑 → 写 llmstate.json → 重启机器人

支持的三点：
1. **URL 可以粘官网控制台页面地址**。例如 `https://opencode.ai/console/wrk_xxx/go`
   会自动映射成 `https://opencode.ai/zen/go/v1/chat/completions`；也能直接填 `.../v1` 或完整端点
2. **先验证再切换**。切之前发一个极小请求，跑不通就不切，原配置完整保留
3. **自定义请求头**。写法：
       HTTP-Referer: https://example.com
       X-Title: MyBot
   多个头换行 / 逗号 / 分号分隔，冒号或等号都认。
   直接回车 = 保持当前的头；输入 `-` = 清空。
   自定义头放在请求头最后，可以覆盖默认头（有些中转站要 X-Api-Key 而不是 Bearer）。

配置文件优先级：**llmstate.json > config.mjs**。
llmstate.json 存 llmUrl / llmKey / model / modelList / llmHeaders；
删掉它就恢复 config.mjs 的默认值。

命令行直跑（不交互）：
    bun run switch-model.mjs --show                      只看当前配置
    bun run switch-model.mjs <url> <key> [model] [headers]
    bun run providers.mjs <url> <key> [model] [headers]  只探测不切换

群内**没有** #接口 / #切换 指令 —— 换模型是本地管理操作，刻意不开放给群里。

## 四、自检

双击 `复检.cmd`，或在 `qq-group-bot\` 下跑 `bun run selfcheck.mjs`。
12 项打勾体检表（基础 5 + 功能 7）：

| 类 | 项目 |
|---|---|
| 基础 | 运行时 / 配置文件 / QQ 进程 / SnowLuma 进程（查唯一性）/ 机器人进程 |
| 功能 | 管理后台 / OneBot HTTP / OneBot WS / QQ 身份 / LLM 对话 / 网络搜索(MCP) / 吃什么抽签 |

状态符号：√ 通过、× 异常、· 等你注入（注入后自动变绿）。
「吃什么抽签」真跑 6 轮抽签；「网络搜索」真调一次 MCP。
自检的 LLM 请求头和 bot.mjs 完全一致（Bearer + x-opencode-session + 自定义头），
否则会出现「自检能过、聊天不通」的假象。
foods.mjs / exa.mjs 若被改坏，自检会报「加载失败」而不是整个表崩掉（动态导入兜底）。

## 五、SnowLuma 侧

| 项 | 值 |
|---|---|
| 版本 | v1.14.22（完整版，内置 Node v22.13.0） |
| WebUI | http://127.0.0.1:5099（5099 被占会自动退 5100，日志有 WARN） |
| OneBot HTTP | http://127.0.0.1:3000/ |
| OneBot WS | ws://127.0.0.1:3001/ |

必须用自带 node.exe：`native\` 下的 .node 原生模块与它 ABI 锁定，换系统 node 会加载失败。

HTTP 和 WS 是两套独立令牌（`config\onebot_<你的QQ号>.json`）：
- HTTP 对应 networks.httpServers[0].accessToken
- WS 对应 networks.wsServers[0].accessToken

其他配置：config/onebot.json（全局）、config/onebot_uin.json（每账号）、
config/runtime.json（端口、hookAutoLoad、日志级别）。

**发图实测**：OneBot v11 的 image 段可用，`base64://` 直传成功。
要点：过小/过假的图会被 QQ 拒收。

## 八、自定义改造：更换 API 与改人设提示词

### 8.1 更换 LLM API（三种姿势）

**姿势一：双击「切换模型.cmd」（推荐，防呆）**

    输入接口地址（例 https://opencode.ai/console/wrk_xxx/go 或完整端点）
    → 输入 API Key
    → 自动拉 /models 模型列表
    → 选序号或输名字
    → 自动发极小请求验证
    → 通过才写盘 llmstate.json 并重启机器人

   安全设计：**验证失败就不切**，原配置原封不动；机器人不会哑。
   URL 智能识别：控制台页面地址会自动映射成 API 端点（见坑 26）；
   没写版本号的地址自动补 `/v1/chat/completions`。

**姿势二：命令行直跑（不交互，适合脚本化）**

    bun run switch-model.mjs <url> <key> [model] ["HeaderA: 1, HeaderB: 2"]   # 切换
    bun run providers.mjs <url> <key> [model] [headers]                       # 只探测不切换
    bun run switch-model.mjs --show                                           # 只看当前配置

**姿势三：直接改 config.mjs（改默认值）**

| 字段 | 说明 |
|---|---|
| `llmUrl` | chat/completions 端点（OpenAI 兼容） |
| `llmKey` | Bearer 鉴权密钥 |
| `model` | 模型 ID——**用 /models 列表核对，别凭官网页面猜**（坑 21 教训） |
| `llmHeaders` | 自定义请求头对象，放最后可覆盖默认头（有些中转要 X-Api-Key 而非 Bearer） |
| `thinking` | `{type:'auto'}` 自动思考 / `enabled` 强制 / `disabled` 关闭 |

**优先级与回滚**：运行时 `llmstate.json` > 默认 `config.mjs`；删掉 llmstate.json = 回滚到默认。

**换服务商先探四件事**（新服务商最容易栽的地方）：
1. 基础生成能不能通（providers.mjs 直接验证）
2. 思考参数认不认（各家不一样，坑 9；无效值可能被静默当成 enabled）
3. 工具调用能不能用（多轮工具循环里有的要回传 reasoning_content，坑 30）
4. 图片/视频视觉支不支持（GLM 系图片只吃 base64 不吃外链，坑 21）

注意：`x-opencode-session` 只有 OpenCode Go 需要，换到别家可以删掉这个头（多带一般无害）。

**换生图 API**：改 config.mjs 的 `imggenUrl` / `imggenKey` / `imggenModel` / `imggenSize`
（OpenAI 兼容 /v1/images/generations 端点；模型返回 b64_json 或 url 都认）。

### 8.2 更改人设 / 提示词

人设和提示词全部集中在 `qq-group-bot/config.mjs`，改完**重启机器人生效**（启动时现读）。

**① `systemPrompt` —— 人设主战场**

现在的结构（改的时候保持四段别散）：
- **角色设定**：性格特征、说话风格（比如「呆呆的、爱撒娇、猫语气」）
- **三条铁律**：绝不承认某身份、不讨论 AI/系统内部话题、被问「是什么模型」一律按人设回避
- **能力边界声明**：能看什么（图/视频）、听不了什么（语音），收到时怎么如实回答
- **行为约束**：别主动提及用户没提的内容、别自己拐话题

写人设提示词的经验：
- 铁律写成**明确禁令**（「绝不…」「不…」），别写成模糊的「尽量」
- **提示词劝不住的行为要上代码闸**——比如「不许谎报看图结果」光靠提示词没用，
  要用检测 + 打回的代码逻辑兜底（坑 31 的教训）
- 声明能力边界能让模型「如实说做不到」，而不是编内容糊弄

**② `eatPrompt` —— 「#吃什么」推荐语的语气**（菜名是脚本抽的，模型只写文案，改这里不影响随机性）

**③ `beaconTrigger` / `beaconReply` —— 寻呼信标词**（触发词别用日常聊天常用语，会误触发）

**④ 改完验证三步**：
1. 跑 `复检.cmd`（12 项自检，确认没改坏配置结构）
2. 重启机器人（再点一次「一键启动」）
3. 群里 @ 它聊两句，验证人设和回答风格对味

### 8.3 其他可调项速查

- 改触发词 / 信标：config.mjs 的 beaconTrigger / beaconReply（见 8.2 ③）
- 改回复长度预算：maxReplyChunks（目标条数）× chunkChars（单条字数）
- 改压缩策略：contextTokenLimit / compressRatio / keepRecent
- 改图片关联窗口：mediaMemoryWindow（按互动次数）/ mediaHistoryMaxBytes（体积闸）
- 加新指令：bot.mjs 的 COMMANDS 加别名 + handleCommand 加分支
- 加新工具：bot.mjs 的 TOOLS 数组加定义 + runTool 加分支（搜索类的实现在 exa.mjs）
