# 更新公告

> 按时间倒序记录每次版本改动。功能性改动会同步更新 README 与 docs/01~03（深度同步偶有滞后，以本公告 + git log 为准）。

## English Summary (latest)

**Oct 27, 2026 — voice stack moves to ByteDance Doubao:** talking switched from MiMo to the **Doubao voice model 2.0** (commander-picked voice `zh_female_roumeinvyou_uranus_bigtts`) via ByteDance's official seed-tts protocol — not OpenAI-compatible: `X-Api-Key` + `X-Api-Resource-Id` headers, a `req_params` wrapper, and an HTTP-chunked response of concatenated JSON objects that has to be split by brace-depth scanning. Two protocol quirks are welded in code: the stream-end signal is `code=20000000 / message="OK" / data=null` (the official docs claim any non-zero code is a failure — reality disagrees, so the body wins), and the streamed WAV header carries a placeholder RIFF size, so the format is mp3. The voice design now travels as `context_texts` speech instructions (exclusive to 2.0 voices, not billed); MiMo stays as a fallback. **Tone became reactive**: `generateSpeech` gained an `upstream` param that quotes the user's triggering message into `context_texts` (official Query-Response pattern — referenced, not synthesized), and a real adapter bug got fixed along the way: `context_texts` honors **only its first element**, so base design + tone directive + upstream must be merged into a single string or the rest is silently dropped. **Auto-voicing threshold lowered 300 → 50 chars** — only short quips get voiced first, longer replies stay as plain chunked text (the explicit `语音：` route is unaffected). **Singing moved to Seed Audio 1.0** (Doubao's audio-generation model): `POST /api/v3/tts/create` with a *flat* `{ model, text_prompt }` body — a different shape from the TTS endpoint — responding `{ audio: base64 wav }`; it's prompt-driven so lyrics are guided rather than literal (it can't be forced to sing exact lines), comes with a 60-minute free trial, and `singCreate` only accepts a custom `ttsSingUrl` that points at bytedance.com (mis-feeding the MiMo borrow endpoint can't blow up the request shape); the MiMo preset-voice `(唱歌)` path remains as the fallback for non-Volcano setups.

**Oct 24, 2026 — review hardening:** an external code review produced 13 findings, all verified real, fixed in three batches. **① Timeout gates** where they were missing: the Exa MCP rpc (a hung endpoint used to stall an entire @-reply silently, zero errors) and the panel's model-list fetch; the anti-lie gate now echoes the model's lying message back before the call-out (it used to "get scolded out of nowhere"); the `语气指令` tone line and the `〔视频描述〕` trailer line are now extracted order-independently — the old parser could swallow the video description, and since the video itself never enters context that meant permanent memory loss; the context compressor now calls the LLM bare (no persona, no tools). **② Key sinking:** config.mjs carries placeholders only — byte-identical between the live copy and this repo, so mirror sync is now a plain directory copy with zero manual steps; real keys live in gitignored runtime files (`secrets.json`: LLM key + OneBot tokens; `mediaapi.json`: all image/video/TTS fields including the voice design), and the panel gained a TTS card. **③ SSRF gate:** `assertSafeUrl` in providers.mjs — http/https only, rejects loopback/private/link-local hosts by literal check *and* by DNS resolution (anti-rebinding), explicit host:port allowlist; wired into the bot's media downloader (group members can stuff URLs into messages — and it also gained its missing 60s timeout) and the panel's three fetch-on-URL endpoints, with Ollama's 11434 as the only local exemption.

**Oct 22, 2026 — draw-route & image-API fixes:** the draw-intent gate now accepts detailed requests up to 5000 chars (the old 80-char cap silently rejected numbered requirement lists and let the model "mouth-draw" a fake success); the image-prompt translator got new iron rules — numbered/negative requirements must survive into the prompt item by item, equipment nicknames map to official English names (e.g. Challenger 2 "Black Night"), 40–120 words; `imggen` now supports both OpenAI-style (`size`/`quality`) and xAI Grok-style (`aspect_ratio`/`resolution`/`quality`, defaulting to medium — omitting quality means auto=low) parameter sets; the config panel's image/video cards gained a model-list fetch button with searchable dropdown (new `POST /api/media-models`, via `mediaModelsUrlOf`).

**Oct 21, 2026 — API panel upgrade:** local web config panel (bind 127.0.0.1, token-protected, keys always masked) with provider presets (OpenCode / CommandCode / DeepSeek / Kimi / BigModel / SiliconFlow / OpenRouter / Ollama); automatic 4-point probe (basic generation / thinking modes / tool calling / vision) via panel or `--probe`; per-message feature switches (`switches.json`, effective instantly, no restart); media-gen API config (`mediaapi.json`, restart required); custom prompts (`prompt.json`); config profiles. Earlier today: text-to-video (async submit/poll/download, 15s cap, download retry), text-to-image with intent-forced routing, honest error reporting for audit blocks / rate limits / quota exhaustion (relay disguises "no money" as HTTP 429), OneBot token leak remediated (history rewritten + force push + rotated + verified via fresh clone).

> 中文详细版见下方各小节。

**Oct 23, 2026 — voice replies & singing:** Cheshire now speaks. QQ voice sending turned out to be fully supported (SnowLuma's record segment ships a native ffmpeg addon that converts any mp3/wav/URL/base64 into NT SILK automatically — the old "voice unsupported" note is obsolete). New `tts.mjs` calls Xiaomi's official MiMo TTS (`mimo-v2.5-tts-voicedesign`, OpenAI-compatible, free during promo) where the voice is *described in natural language* — replies ≤300 chars are auto-voiced first with a text copy after, and the LLM appends a per-message "tone directive" so every voice message has its own mood. Triggers for explicit voice requests: `语音：…` / `说一段…` / `用日语说…`. Singing got its own route (`唱歌…` → LLM writes lyrics → `(唱歌)` tag on the preset-voice model — singing is preset-voice-exclusive per official docs, so talk uses the designed voice while songs borrow a preset timbre). Also fixed: the redraw router read a stale last-prompt when the image came from the model's tool call (tools now book-keep too), and the anti-lie gate now catches the `[已画图: …]` fake marker which is stripped from all outgoing text.

  ①流结束信号是 `code=20000000 / message="OK" / data=null`——官方文档说「非 0 即失败」与实测不符，
  按 body 实情特判放行（坑 37 同族：错误分类看 body 别盲信文档）
  ②流式块拼出来的 wav 头 RIFF 尺寸是占位符 → 音频格式改 **mp3**（帧格式无尺寸隐患）
- **声线控制换形态**：`ttsVoiceDesign` 在豆包模式转成 `context_texts` 语音指令
  （2.0 音色专属、**不计费**）；动态语气照旧追加
- **配置落点**：mediaapi.json（gitignored）= 豆包 Key + ttsVoice + ttsModel(seed-tts-2.0)；
  config.mjs 补占位默认值 + **mediaapi 覆盖白名单 +3**（ttsVoice/ttsSingUrl/ttsSingKey）
  ⚠️ 面板 TTS 卡暂不显示这三个新键（merge 写入陌键存活，手改 mediaapi.json 重启即可）

### 🧠 语气实时化（官方 Query-Response 范式落地）
- `generateSpeech(text, tone, upstream)` 新增第三参 **upstream**：把触发语音的那句用户原话
  喂进 `context_texts`（只引用不合成，模型自动承接语境情绪，不用 LLM 多申报任何东西）；
  语音路由传诉求原文、自动语音化传触发消息，两处调用都挂上
- **揪出适配 bug**：官方口径 `context_texts` 数组**只第一个元素生效**——此前传
  [底色, 语气] 两条，动态语气被静默丢弃；修正为底色+语气+上文拼成一条单串
- **能力边界调研（官方文档口径）**：uranus 音色没有 `audio_params.emotion`（1.0 emo 家族专属）；
  SSML 只有 `<break time>` 对语气有用；无 [laughter] 式 inline 标记（ICL 复刻音色专属）；
  逐句换语气 = 每句一次请求各自带 context_texts（官方无 per-sentence 指令通道）

### ⚡ 自动语音化阈值 300 → 50 字（指挥官指示）
- config `ttsAutoVoiceChars: 50`：只有 ≤50 字的短回话先发语音+文字版跟上，
  更长的回复回归纯文字分段连发；「语音：」路由不受影响（160 字截断、800 字硬顶）

### 🎵 唱歌切 Seed Audio 1.0（豆包音频生成模型，prompt 驱动演唱）
- 说话走豆包时 `generateSong` 改走 `POST /api/v3/tts/create`：**扁平请求体**
  `{ model: 'seed-audio-1.0', text_prompt }`、响应 `{ audio: <base64 wav> }`——
  **和 TTS 的 req_params 嵌套不是一套形状**（同一服务商不同接口形状也会不同，逐接口实测）
- prompt 组合 = 声线描述 + 演唱风格 + 歌词一条自然语言；**不精确控歌词**
  （「给这几句歌词唱出来」做不到，「唱一小段气氛歌」可以）；**60 分钟免费试用（有效期半年）**
- **防御**：`singCreate` 只认指向 `openspeech.bytedance.com` 的自定义 `ttsSingUrl`，
  其他一律用官方默认端点（防误喂 MiMo 借道地址形状炸掉）；
  非火山场景（克隆用户）保留 MiMo `mimo-v2.5-tts` 预置音色回退（`(唱歌)` 标签路径原样）
- **真测**：30 字歌词合成 1.74MB wav / 14.7s，样片发群 retcode 0，重启 + 自检 12/12 全过
